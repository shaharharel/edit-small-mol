1The three training phases

The model is taught covalent medicinal chemistry in three rungs, each one presupposing the last. Rung 1 teaches what a covalent reaction is. Rung 2 teaches how to edit a molecule without breaking it. Rung 3 asks for the real job: given a pocket and a covalent hit, propose a better covalent analogue and say why. A fourth channel, the potency head, runs across rungs 2 and 3 and is the only part of the system that outputs a number rather than text.

Phase 1Reaction chemistry 373,935 rows · 63.9%

Four subtasks that force the model to represent the covalent bond-forming event itself, not just the molecules around it. ADDUCT applies the reaction forward; RETRO inverts it; SELECTIVITY names the residue attacked; WARHEAD_ID names the electrophile class. Together they are the vocabulary the later rungs assume. No pocket is shown at this rung — these are properties of the ligand alone.

A real defect in this rung, found while compiling this report. 1,088 of 68,868 rung-2 rows (1.58%) carry a degenerate transform label of the form substitute X -> X — for instance substitute Cl -> Cl, emitted when the chloro moves position on a ring: the labeller names the atom swapped but not the position moved, so the label reads as a no-op. It is small enough not to justify restarting a run that is 39% complete, and it is logged here rather than quietly fixed.
Phase 3Covalent hit-to-lead, pocket-conditioned 3,015 unique · 2.1%

The target task. The model is given the hit and its own co-crystal pocket, expressed in the covalent reaction frame: the attacked electrophilic atom sits at the origin, the attack axis is +z, and +x points toward the Murcko-scaffold centroid. That frame is the reason the geometry generalises across complexes — every pocket is expressed relative to the chemistry that is about to happen, not to an arbitrary crystallographic axis.

The output is a full medicinal-chemistry rationale, not a bare SMILES: the structural Change, the Intent (is this edit for recognition, for reactivity, or both), the Warhead move, the contacts it Gains and Loses, and only then the Analogue.

Rung 3 — a real labelled row (7KRF, P03366)

The label swaps that warhead to a haloacetamide and extends the linker, trading four contacts away for four others including a new TYR188 hydrogen bond. The LIGAND block lists every heavy atom in frame coordinates; the POCKET block gives the 20 nearest of 43 residues by minimum distance.

This is the single most important number for calibrating expectations on rung 3, and it is a property of the data rather than the model.

The median rung-3 "analogue" shares only Tc 0.436 with its hit. 39.5% of pairs sit between 0.30 and 0.40, and the miner enforces a hard floor at 0.30 — no pair falls below it. These are programme-level jumps across a real optimisation campaign, not tight matched molecular pairs, which is why exact recovery of the reference analogue is a very demanding metric here. It also reframes v4's headline failure: a best-of-20 output at Tc 0.378 to the reference, when the reference is itself only ~0.44 from the hit, means the model landed about as far from the target as its own input did.
A second real defect, worth stating before any result is read. 308 of 3,015 rung-3 rows (10.2%) have Warhead: SWAP_TO:none — the "improved" analogue has no electrophile at all. These are mined from real covalent programs where a team abandoned the warhead, so they are genuine medicinal chemistry, but they contradict the instruction the model is given ("keep the warhead"). They will inflate any warhead-retention metric's apparent error. §7 therefore reports warhead retention on the KEEP subset separately.
Channel 4The potency head 130,667 rows · 22.3%

A Siamese MLP over [hit_vec, ana_vec, ana_vec − hit_vec], reading the final hidden state through a forward hook, trained with a masked regression loss so unlabelled rows contribute nothing. It predicts ΔpIC50 — the potency gain of the analogue over its hit — and it is the piece of v3 that had to be rebuilt from scratch.

The v3 leak is dead in the data, not just at train time. Every v3 potency number was void because the response span contained the literal line Predicted dpIC50: +1.32 — inside the very span a response-pooled head reads, so the head could read its own answer. v3b stripped it in the trainer, which left the defect one forgotten flag away from returning. v4b strips it in the corpus: a scan of all 585,530 training rows finds 0 whose output mentions dpIC50, and the build refuses to write a file that fails that check.

2What was thrown away, and why

Rung 3 is the task that matters and the task with the least data, which makes it the easiest place to accept bad rows. 31.7% of what the miner offered was rejected.

The biggest single gate is the one nobody would think to write. 1,527 rows — 27.6% of everything offered — had a LIGAND coordinate block whose atom count disagreed with the Hit SMILES by more than ±25%. The pocket geometry in those rows describes a different molecule than the SMILES the model is asked to edit, which would have taught the model to ignore the geometry. The gate compares ligand-block atoms against the hit's heavy-atom count and demands a ratio in 0.80–1.25.
Post-gate integrity checks, run against the actual training file. All 12,060 rung-3 analogue SMILES parse under RDKit (0 failures). 0 rows carry the dpIC50 leak. Change: NONE survives on only 16 of 3,015 rows (0.5%).

3How the held-out sets are built

v4 had a held-out split for rung-3 generation only, which is why it has no validation loss, no early stopping and no per-rung evaluation. v4b splits all four channels, each on the key that makes memorisation useless.

channelsplit keyheld outwhy this key
rung 1input molecule32,082all four subtasks key off the same molecule, so a row-level split would let a test molecule reappear under another subtask
rung 2deduplicated pair5,988pair-disjoint; 4,385 duplicate pairs (5.5%) were removed first, after a random split put 600 test pairs’ twins into training
rung 3deduplicated pair334same construction; 431 duplicates removed
affinityhit group12,408the metric is within-hit Spearman, so every analogue of a hit must land on one side or the metric is undefined
Deliberately not a component split. v4's rung-3 fold assigned whole connected components of the molecule graph, which put test molecules at median max-Tc 0.357 to training — below the Tc ≥ 0.40 that rung 2 itself uses to call two molecules analogues at all — and collapsed the fold into ~3 chemotypes, so the effective chemical n was 3, not 1,017. That is a worst-case probe, not a measurement. v4b uses pair-level disjointness and instead tags every test row with its max ECFP4 Tanimoto to training, so difficulty tiers (all, ≤0.8, ≤0.7) become a reporting choice from one checkpoint rather than a corpus decision requiring a retrain.

Read the three label fields against their floors, not against 100%. Intent is 75.2% RECOGNITION and Warhead-move is 77.0% KEEP, so a 78% accuracy on either is roughly nothing learned. This is the exact error v4 nearly shipped: a 49.4% change-op score read as failure until a conditional-entropy audit showed only 1.099 of 2.047 bits of the field are recoverable from the input at all, putting the Bayes-optimal ceiling at 64.7% — so 49.4% against a 37.2% floor was most of the available signal, not a shortfall.

11Compute note — the run is launch-bound, not compute-bound

Worth recording because it is a config error, not a hardware limit, and because it changes what the next run should do.

The cause is a batch size carried over from a corpus of the opposite shape. --bs 3 was correct for v4, where rung 3 dominated at ~2,200 tokens a row, so a micro-batch was ~6,600 tokens and the A100 was well fed. v4b inverted the mix: rung 1 is now 63.9% of rows at 53 tokens each, so the same bs 3 ships ~389-token micro-batches. 63.9% of all wall-clock is spent on rows that are 1/28th the size of a rung-3 row but cost nearly as much, because the cost is per-op CPU dispatch — roughly 6,000 dispatches per micro-batch once LoRA's 196 adapters and the gradient-checkpoint re-forward are counted, at ~94 µs each — and not FLOPs. Hence 48% utilization, 181 W of 400 W, and one CPU core pinned while 11 sit idle.

The fix preserves the optimization exactly. Batching to a token budget rather than a fixed sequence count keeps the effective batch at 33 examples per step while collapsing 11 micro-batches into 1, giving an identical gradient with 21× fewer launches across the epoch. Long rung-3 rows overflow the budget and simply accumulate more steps. Validation gets the same win for free: it currently runs 1,000 forward passes of 3 rows every 500 steps, about 6% of all wall-clock, and would drop to ~50. Gradient checkpointing should then stay on, because it is only wasteful while batches are this thin.
