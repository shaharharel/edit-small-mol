Interpretation:
  InfoNCE contrastive term DOES install pose->hidden alignment (val_pos_wins 0.60-0.88 vs random 0.20).
  Regression head DOES learn to predict target from h_pooled (val_spearman up to 0.488 for composite).
  BUT neither pathway carries through to the decoder generation stage. When we clamp the pose input to
  best-quartile-mean or worst-quartile-mean, the emitted SMILES converge to the same canonical
  planar-acrylamide mode regardless. The h_pooled *does* differ across clamps (reg_head_prediction
  shifts by 0.02-0.07 z-units), so the pooled hidden state is not fully saturated -- but the decoder
  greedy path collapses back to the training modal geometry.

  This mirrors the prior InfoNCE-only finding on the same architecture (from_infonce_DONE.txt).
  Switching to the correct target (ZAP70 real-PAE with mpae_warhead_cys measured directly at Cys346)
  does NOT change the result. Data-signal wall is likely fundamental to the InfoNCE+regression-head-
  on-pooled-hidden design. The pose channel has only two entry points (pocket_vec, pose_vec) as
  single memory-side tokens that are diluted across the whole decoder. To install true geometric
  steering the pose likely needs FiLM-conditioning each decoder layer, or an explicit pose-token
  cross-attention head, or a wider empirical distribution over off-canonical poses in training.
